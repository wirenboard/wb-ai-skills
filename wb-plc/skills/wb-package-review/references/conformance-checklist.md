# Conformance checklist — what to add on top of the template

The rules and examples live in the template and codestyle repos — read them, don't restate them:

- <https://github.com/wirenboard/wb-python-service-template> — layout, `--version`, versioning,
  MQTT lifecycle (Last Will, clearing retained topics), config + schema + `wb-configs.d`, unit
  file, Debian packaging, tests, README. Its "Перед контрибьютом" section is the stand checklist.
- <https://github.com/wirenboard/codestyle> — type annotations, docstrings, lintian profile.

Map each template rule to the unpacked `.deb` (`dpkg-deb -R`) and mark it ✅ / ⚠️ / ❓. The
checks below are **not** in the template (Debian policy, systemd behaviour, issues seen in
reviews) — cite them as review findings, not as template violations.

## Extra checks

| Check | Where to look |
|---|---|
| Hand-written `python3` next to `${python3:Depends}` (expanded as `python3:any`) | `dpkg-deb -f pkg.deb Depends` |
| Maintainer scripts generated by debhelper | `# Automatically added by dh_installsystemd` blocks; hand-rolled `deb-systemd-helper` calls mean they were written manually |
| Every service's error exit codes are in its own `RestartPreventExitStatus` | each unit vs the code its entrypoint exits with |
| Timer-fired oneshots tolerate being stopped (`SuccessExitStatus=SIGTERM` or a handler) | `.timer` + `.service`, `DEBIAN/prerm` |
| Timers that only act on a condition are gated (`ConditionPathExists=`) | `.timer`/`.service` |
| Purge removes everything the package created | `DEBIAN/postrm` vs `StateDirectory=`, state/backup/lock dirs |
| No expensive work in loops (e.g. schema validation every tick) | main loop, timer entrypoints; size of the confed schema |
| Type annotations / one-line docstrings without the source tree | `ast` walk over all `.py` in the package |

## Web UI exposure

| Check | Where to look |
|---|---|
| No own nginx include that proxies a web UI past the homeui login | `etc/nginx/includes/default.wb.d/` |
| On releases with homeui service gates: `gates.d/<name>.json` + `wb-homeui-gates apply` in `postinst`/`postrm` | `usr/share/wb-mqtt-homeui/gates.d/`, maintainer scripts; `wirenboard/homeui` `docs/wb-service-gate-howto.md` |
| The app works behind the gate: relative paths, no `Origin`-vs-`Host` port mismatch, no hard-coded old path | static files, request handlers |
| Own authorization kept for configuration-changing UIs (gate `role` is not enforced for cloud-tunnel requests) | app auth code |

## Not checkable from a .deb — list as ❓

`Build-Depends`, `debian/rules`, `pytest.ini`, `tests/`, `Jenkinsfile`, `.gitattributes`. Ask the
author for the source or CI link if these matter.
